# JobRunner

Durante el semestre, cada equipo desarrollará un sistema para Linux capaz de ejecutar, administrar, observar y controlar trabajos. El producto deberá funcionar localmente y permitir operación remota dentro de una red privada, LAN o VPN.
Cada equipo podrá asignar un nombre propio a su implementación. JobRunner es el nombre utilizado en las especificaciones para identificar el producto solicitado.
El proyecto se realizará en equipos de 3 integrantes; podrán autorizarse equipos de hasta 4 integrantes.

## Documentos del cliente
Antes de comenzar, el equipo deberá revisar los seis documentos de especificaciones:
- Project Brief
- Requisitos funcionales
- Requisitos no funcionales
- Estándares de repositorio e ingeniería
- Plan de verificación, validación y aceptación
- Hitos y revisiones técnicas

Estos documentos constituyen la línea base del proyecto. Las dudas que puedan modificar el comportamiento esperado deberán consultarse antes de asumir una interpretación.

## Forma de trabajo
El cliente especifica qué debe cumplir el producto, pero no impone una arquitectura única. Cada equipo deberá tomar y defender decisiones relacionadas con:
- Lenguaje y herramientas.
- Arquitectura.
- Procesos, concurrencia e IPC.
- Persistencia y recuperación.
- Protocolo de red.
- Cancelación de trabajos.
- Saturación y manejo de recursos.
- Acceso mediante LAN o VPN.

Las decisiones técnicas relevantes deberán documentarse mediante ADR.

El uso de inteligencia artificial y vibe coding está permitido. El equipo será responsable de comprender, revisar, probar, modificar y defender todos los artefactos entregados.

## Repositorio
Todo el trabajo deberá mantenerse en un repositorio Git. Las tareas significativas se administrarán mediante Issues y deberán relacionarse con implementación, pruebas y evidencia.

El repositorio incluirá, como mínimo:
- Código fuente.
- README.
- Guía de usuario.
- Guía técnica.
- ADR.
- Registro de uso de IA.
- Plan y casos de verificación.
- Matriz de trazabilidad.
- Evidencia de resultados.
- Planeación, roles, acuerdos y minutas.
- Cambios e incidentes.

## Responsabilidad individual
- Cada integrante deberá ser responsable principal de una parte técnica, participar en la verificación de una parte distinta y producir artefactos que pueda defender individualmente.
- Que el sistema funcione durante una demostración no será evidencia suficiente. El equipo deberá demostrar cómo verificó los requisitos y cada integrante deberá comprender el producto entregado.
- El proyecto tendrá dos avances formales, dos revisiones técnicas y una entrega final con defensa individual.
